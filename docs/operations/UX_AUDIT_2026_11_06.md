# Access, documentation and email UX audit

## Scope and evidence

The audited product is the existing cluster application at `https://bmycure4mm.clusterlab.uk`, not a new demo site. Public documentation, registration and mobile login were captured before changes. Owner QR usability was reported directly by the owner and reproduced with synthetic owner accounts. Email presentation was inspected through the actual templates and isolated SMTP sink. Production owner credentials, MFA seed, activation links and private tickets were not captured.

Before screenshots were taken on source `f4d8dde88648e54e636188ae77b84fd80e1f83b5`. Hardening source `2d464f68341378186c156e413cdcafa2dbfd84cd` subsequently deployed QR and email improvements. The documentation fixes subsequently deployed in reviewed source `55a556b0c5cf4b8dc95ef6be6d0a6bc873cc1a3c`, digest `sha256:56a4beb7e54153f7cba30af4de3e5240feb2f23265e9702b33f0f7e19c43f80d`. Product-domain desktop documentation and mobile Italian request/login pages were captured after rollout; math, diagrams, all four model figures and static asset MIME types were verified. Saved visual evidence is local and sanitized; filenames below identify the captured steps. They are not public links or proof of human acceptance.

## Additional code-confirmed workflow blockers

Following the browser path into the existing simulator exposed two functional problems that were not visible in the initial documentation captures. Numeric widgets had permanent `readonly` attributes without an active control to unlock them. Result buttons also pointed directly at `/media/` artifacts, which production correctly does not expose. These are implementation findings, not claims derived from a screenshot alone.

The correction makes the existing numeric widgets editable while preserving every field, unit, validator, bound and scientific default. Plot and CSV buttons use authenticated routes for the selected run, including current access-state checks and private/no-store responses. No media directory is exposed. The browser test edits inputs, performs two real calculations, reads the Plotly chart, exports its CSV and checks cross-user export denial before submitting feedback.

## What was preserved

The visible E1/research warning, labeled email/password fields and the mobile layout's lack of horizontal overflow were useful foundations. This work extends the existing Bootstrap and English/Italian conventions rather than introducing a design system or another application. Shared scenarios and their scientific parameters are unchanged.

## Verification and limits

The automated browser journey uses real HTTP forms, CSRF, password login, two separate members, owner TOTP and an isolated SMTP sink. It now checks the documentation handbook at 1280 and 390 pixels: rendered math, Mermaid SVG, loaded public figures, code-copy controls, Italian form labels and absence of horizontal overflow. Unit tests cover relative document links, anchors, rendered front matter, Markdown-only paths and external symlink denial.

Production smoke is separate from this synthetic browser evidence. The owner personally completed first login and MFA; no researcher was approved by automation. Actual Gmail SMTP authentication and owner-email receipt were verified separately from email presentation tests. A successful email preview does not prove inbox placement or spam reputation.

This is not a full WCAG certification or a full clinical/research workflow audit. Assistive technology, a human unfamiliar with the platform, all legacy advanced-tool pages and the independent forensic-atlas maintainer exercise remain unverified. Production owner-console screenshots are intentionally absent to avoid exposing real requests or identities; synthetic desktop/mobile console tests provide bounded evidence. Issue #79 and researcher acceptance #78 remain open.

### Evidence and bounded verification

Local final discovered suite: **473 tests PASS in 34.482s**, macOS ARM64/Python 3.11 with disposable SQLite. Ruff, format, mypy, repository hygiene, atlas drift, numerical baseline (zero differences), frozen dependency audit and strict MkDocs build passed. Deploy checks retain the documented SAMEORIGIN framing warning for authenticated embedded plots; no migration drift. Browser and target-image execution are separate checks below and in the release ledger.

Fresh public production captures before this follow-up are `01-docs-before.png`, `02-handbook-before.png`, `03-handbook-mobile-before.png`, `04-request-mobile-before.png` and `05-learning-empty-before.png`. Separate isolated browser captures contain only generated identities and independent synthetic calculations; no capability URL, password, MFA seed or production request is captured. Saved files are local audit evidence, not public acceptance claims.

Final account browser journey: **PASS in 39.016s**; dedicated public documentation browser: **PASS**. The browser journey uses actual CSRF forms, two distinct nonstaff users, SMTP sink, password login, owner TOTP, two real model calculations, chart/export, private tickets, owner reply and relogin. Additional checks exercise invalid-form focus/data preservation, Italian console controls, real second-page navigation, contextual help failure/recovery and mobile layouts. The public documentation browser checks keyboard navigation, reflow, copy feedback, TOC resize, help errors and computed contrast. Navigation contrast is 4.501:1 and code-comment contrast is 5.194:1; these measured samples are not a whole-site accessibility certificate.

The [developer verification record](../development/AUDIT_VERIFICATION_2026_11_06.md) documents executed commands, measured outputs and the independent human acceptance boundary. No numerical model, default, solver or golden output was changed. The release evidence and exact PR head/image digest are retained in the [release ledger](AUTHENTICATION_AND_ACCESS.md#verified-runtime-evidence-2026-11-06) and linked tracker updates.

### Final boundary regressions

The final adversarial pass also found that a registered user's learning form could populate legacy `DEMO`-prefixed assessment choices before any calculation. The form now applies the existing clinical-access boundary before querying records, hides unavailable Twin workflows, and rejects posted Twin context. Synthetic regression checks cover all three simulator aliases and the nonstaff owner; a name prefix does not grant clinical access. Documentation path checks also validate the resolved symlink target against the same allowlist, including links to non-public files inside the repository. Dual owner-console pagination retains both query parameters.

### Residual limits

Assistive-technology testing by a human, independent unfamiliar-user/maintainer acceptance, all legacy advanced-tool pages and full localization outside this access/learning/documentation path remain unverified. Production owner pages are not photographed; isolated real-login browser evidence covers their controls. No external researcher was approved automatically. The already improved multipart emails remain in use; this audit does not equate SMTP acceptance or template layout with inbox reputation.

## Remaining governed work

The full forensic developer atlas needs an independent maintainer to trace functions, reproduce a failure and explain rollback without AI or secrets. Global compute admission/cancellation, broad clinical RBAC and existing Redis topology are separate open work; they must not be declared solved by this UX correction. External MathJax/Mermaid assets are version-pinned but still require CDN availability, as do the existing Bootstrap assets.
